Configuration#

PyQSense is configured using a YAML file. You may discover the available options here, or read the schema directly in Configuration Schema.

Environment Variables#

PYQSENSE_CONFIG_PATH#

Points to the directory containing the YAML configuration file. Must be set by the user or PyQSense will exit.

PYQSENSE_LOG_PATH#

The directory to write logs to. Default is %LocalAppData%\PyQSense on Windows, and /var/log on unix.

PYQSENSE_LOG_STEM#

The basename of the log file to write. For example, in mylogfile.3, the basename is mylogfile.

PYQSENSE_LOG_LEVEL#

Selects the verbosity of logs. The log level may be specified as an integer or a string, according to the table:

A lower log level means a higher volume of logs and more detail in messages.

Example Configuration#

ttl:
  type: Pulse_Blaster
  channels:
    channel_a:
      channel_number: 0
      start_offset: 3
      width_offset: 11
    channel_b:
      channel_number: 1
      start_offset: 0
      width_offset: 2
cam:
  type: Basler_Camera
  frame_trigger: Line1
  burst_trigger: Line2
mw:
  type: SRS_SG380
  address: "ASRL4::INSTR"
  model_name: Stanford Research Systems,SG380,s/n8888,ver1.520
stage_x:
  type: ThorLabs_Kinesis_Motor
  motor_id: 12345
  limits:
    - 10
    - 75.56
stage_y:
  type: ThorLabs_Kinesis_Motor
  motor_id: 54321
  limits:
    - 0
    - 100
  home_offset: 1.84

  type: ThorLabs_Kinesis_Motor

  limits:
    - 0
    - 100
  inverted: True

Configuration Schema#

This is the JSON schema (in YAML) defining the available configuration options for PyQSense.

# schema for the devices.yaml file parsed by devices.py
$schema: https://json-schema.org/draft-07/schema
title: PyQSense Device Configuration
description: >
  Specify settings for physical devices used in PyQSense
type: object
properties:
  ttl:
    type: object
    description: >
      TTL logic card config
    properties:
      type:
        type: string
        description: >
          Unqualified name of class to load from `ttl_control` module. For
          example, `Pulse_Blaster`.
      channels:
        type: object
        description: >
          TTL channel configurations per channel
        properties:
          channel_number:
            type: number
            description: >
              Output line number. The meaning of this setting is
              implementation-dependent. If using a PulseBlaster, this is the
              output pin number according to the numbering in their C API.
          start_offset:
            type: number
            description: >
              Time (in ns) to add to every pulse start time.
          width_offset:
            type: number
            description: >
              Duration (in ns) to add to every pulse.
  cam:
    type: object
    description: >
      Camera configuration
    properties:
      type:
        type: string
        description: >
          Unqualified name of class to load from `cam_control` module. For
          example, `Basler_Camera`.
      frame_trigger:
        type: string
        description: >
          The hardware trigger source for a single image acquisition. For
          example, "Line1".
      burst_trigger:
        type: string
        description: >
          The hardware trigger source for a burst of images.
  mw:
    type: object
    description: >
      Microwave configuration
    properties:
      address:
        type: string
        description: >
          The VISA resource name of the microwave generator. For example,
          "ASRL3::INSTR".
      model_name:
        type: string
        description: >
          The model name given by the `*IDN?` SCPI command. For example,
          "Standford Research Systems,SG380,s/n1234,ver1.104".
      baudrate:
        type: number
        description: >
          The symbol rate (in baud) of the instrument. This does not set the
          symbol rate, but indicates what symbol rate the instrument expects.
additionalProperties:
  type: object
  description: >
    Auxiliary device configs. The names must correspond to those hardcoded in
    PyQSense, just like the microwave configuration object must be named "mw".
  properties:
    type:
      type: string
      description: >
        Unqualified name of class to load from `aux_control` module.
    additionalProperties:
      # any type
      #type:
      description: >
        Keyword arguments to pass to `__init__` method of the device class.

The devices Module#

The following are technical details not needed for operational knowledge. They are provided for developers.

PyQSense internally references a devices module that enables communication with equipment. The module searches for a file devices.yaml in the directory specified by PYQSENSE_CONFIG_PATH and instantiates abstract classes in PyQSense.aux_control, PyQSense.ttl_control, and PyQSense.cam_control, inserting them into the current module. These instances are bound to the hardcoded identifiers, listed here:

  • ttl (PyQSense.ttl_control.Pulse_Blaster)

  • cam (PyQSense.cam_control.Basler_Camera)

  • mw (PyQSense.aux_control.SRS_SG380)

  • stage_x, stage_y, stage_z (PyQSense.aux_control.ThorLabs_Kinesis_Motor)

Most options for each device are passed directly to the corresponding device’s __init__ method.

Note

Strictly speaking, the device classes do not specifically have to be the ones listed above; they may be any class that implements the same public methods as defined by our concrete implementations in classes such as PyQSense.ttl_control.Pulse_Blaster.
