Configuration
=============

PyQSense is configured using a YAML file.
You may discover the available options `here`_, or read the schema directly in :ref:`devices-yaml-schema`.

.. This link only works when the site is hosted at the root of the filesystem.
   Browsing the site as local files breaks this link. The file is generated by
   json-schema-for-humans.

.. _here: /PyQSense-docs/_static/devices.schema.html

Environment Variables
---------------------

.. envvar:: PYQSENSE_CONFIG_PATH

   Points to the directory containing the YAML configuration file. Must be set
   by the user or PyQSense will exit.

.. envvar:: PYQSENSE_LOG_PATH

   The directory to write logs to. Default is ``%LocalAppData%\PyQSense`` on
   Windows, and ``${XDG_STATE_DIR}/PyQSense`` on Linux, with fallback to
   ``~/.local/state/PyQSense``.

.. envvar:: PYQSENSE_LOG_STEM

   The basename of the log file to write. For example, in ``mylogfile.3``, the
   basename is ``mylogfile``.

.. envvar:: PYQSENSE_LOG_LEVEL

   Selects the verbosity of logs. The log level may be specified as an integer
   or a string, according to the table:

   .. csv-table:: Log Levels
      :header: "Level name", "Level number"

      "DEBUG", 10
      "INSTRUMENT", 15
      "INFO", 20
      "WARNING", 30
      "ERROR", 40
      "CRITICAL", 50

   A lower log level means a higher volume of logs and more detail in messages.

Example Configuration
---------------------

.. code:: yaml

   ttl:
     type: Pulse_Blaster
     channels:
       channel_a:
         channel_number: 0
         start_offset: 3
         width_offset: 11
       channel_b:
         channel_number: 1
         start_offset: 0
         width_offset: 2
   cam:
     type: Basler_Camera
     frame_trigger: Line1
     burst_trigger: Line2
   mw:
     type: SRS_SG380
     address: "ASRL4::INSTR"
     model_name: Stanford Research Systems,SG380,s/n8888,ver1.520
   stage_x:
     type: ThorLabs_Kinesis_Motor
     motor_id: 12345
     limits:
       - 10
       - 75.56
   stage_y:
     type: ThorLabs_Kinesis_Motor
     motor_id: 54321
     limits:
       - 0
       - 100
     home_offset: 1.84
   stage_z:
     type: ThorLabs_Kinesis_Motor
     motor_id: 8433894398348943
     limits:
       - 0
       - 100
     inverted: True

..

     type: "SRS_DC215"
     address: "ASRL6::INSTR"
     model_name: "Stanford Research Systems,DC215,s/n1234,ver1.009"
     baud_rate: 9600
     send_end: True

The ``devices`` Module
----------------------

The following are technical details not needed for operational knowledge. They are provided for developers.

PyQSense internally references a ``devices`` module that enables communication with equipment. The module searches for a file ``devices.yaml`` in the directory specified by :envvar:`PYQSENSE_CONFIG_PATH` and instantiates abstract classes in :py:mod:`PyQSense.aux_control`, :py:mod:`PyQSense.ttl_control`, and :py:mod:`PyQSense.cam_control`, inserting them into the current module. These instances are bound to the hardcoded identifiers, listed here:

.. TODO:DOC is this list comprehensive?

* ``ttl`` (:py:class:`PyQSense.ttl_control.Pulse_Blaster`)
* ``cam`` (:py:class:`PyQSense.cam_control.Basler_Camera`)
* ``mw`` (:py:class:`PyQSense.aux_control.SRS_SG380`)
* ``stage_x``, ``stage_y``, ``stage_z`` (:py:class:`PyQSense.aux_control.ThorLabs_Kinesis_Motor`)

Most options for each device are passed directly to the corresponding device's ``__init__`` method.

.. note::
   Strictly speaking, the device classes do not specifically have to be the ones listed above; they may be any class that implements the same public methods as defined by our concrete implementations in classes such as :py:class:`PyQSense.ttl_control.Pulse_Blaster`.
