📁 ttl_control#

Manage PulseBlaster TTL pulse generators.

Abstraction layer over SpinAPI, the official C library for PulseBlaster cards. Implements a PyQSense.ttl_control.Pulse_Blaster class with methods for starting, stopping, and programming a periodic binary signal to the card.

Note

Some vocabulary:

Instruction word

An 80-bit PulseBlaster processor instruction.

Instruction

Human-readable name given to the opcode field of an instruction word. For example, opcode 6 is named “BRANCH”.

Flags

A 24-bit integer which represents the state of the PulseBlaster output lines. A mapping of each bit to the corresponding output pin number is found in table 2 of Using SpinAPI in C/C++ for PulseBlaster Programming.

class PyQSense.ttl_control.ttl_channel(name, channel_number, start_offset, width_offset)#

Bases: tuple

TTL channel configuration object.

Represents a physical output line (channel) on the TTL card. Offsets to the pulse timings and duration may be specified here. This class is not defined explicitly; rather, it is instantiated by the standard library collections.namedtuple() factory function. Stores offset values that are to be used in PyQSense.ttl_control.Pulse_Blaster._event_scheduler(). Note that the YAML configuration parser expects start_offset and width_offset to be provided in seconds, while internally, the PulseBlaster expects nanoseconds.

class PyQSense.ttl_control.ttl_sequence(name, start_times, pulse_widths)#

Bases: tuple

TTL pulse sequence object.

These objects are representations of one period of periodic binary signal. The signal is represented by the starting time and duration of an “on” pulse.

The information in this object ultimately gets sent through the spinapi C function pb_inst_pbonly which expects an instruction duration in nanoseconds.

program(channel_sequences)#

Program the Pulse Blaster with a new pulse sequence.

Upload a specific pulse sequence to the PulseBlaster. At the core of this method is the pb_inst_pbonly C function which uploads an instruction word to the PulseBlaster’s internal memory. channel_sequences is converted into a series of PulseBlaster instruction words that result in the desired signal when executed. Additionally applies the timing offsets and pulse width adjustments specified in PyQSense.ttl_control.Pulse_Blaster.channels.

The resulting program is a simple loop, consisting of CONTINUE instructions until the last instruction word, which is a BRANCH to the first instruction word. Below is a table representing the common structure of PulseBlaster programs generated by this method. The delay count is usually that specified by the time difference in the return value of PyQSense.ttl_control.Pulse_Blaster._event_scheduler() (in the table, times is a list returned by that method), except when the pulse duration is short enough that the PulseBlaster’s short pulse feature is required. In that case, the delay count is 5 clock cycles, but the electrical signal is not on for the full duration. See here for the instruction set architecture specification and more information about the short pulse feature.
